# 骗子酒馆 模型美化与性能 设计文档

- 日期:2026-10-07
- 状态:已确认(用户授权按此文档自审推进);子项目① 已实现(2026-10-08,未发版),②③④ 待实施
- 分支:`feature/liars-tavern-mvp`
- 依据:只读审计(5 个子审计 + 汇总,含离屏实测)与 10 个机位的美化前截图
- 关联:总规格 `docs/superpowers/specs/2026-08-14-liars-tavern-design.md`(本文只改其中「3D 表现」与「等待厅/协议」中形象分配相关的部分)

## 1. 背景与目标

现在所有 3D 模型都按「一个基础几何体 = 一个 `MeshInstance3D` + 一份新建网格 + 一个 `material_override`」拼装
(`src/world/mesh_kit.gd:5-14`),结果是:

- **外形简陋**:角色是胶囊躯干、球肩、直管手臂、连指手套爪、「球上粘球」的脸;耳朵穿过帽檐;没有腿和尾巴;
  浅色角色在烛光下过曝(猪脸 63–84% 像素削顶)。场景墙面平板、四周空荡、吧台是方盒;左轮细小如棍、被爪子吞掉。
- **draw call 贵却没换来细节**:展台场景 749 个实例、seat 视角约 1800 次/帧,其中 67% 在阴影 pass;
  749 个实例只对应约 300 种参数组合,却没有任何网格共享,Forward+ 的自动实例化从不触发。
- **帧时间不在几何上**:M3 上 9.7 ms/帧主要花在 SSAO(约 1.5)、体积雾(约 1.2)、辉光(约 0.7)和烛光(约 0.7)上,
  draw call 从 1799 降到 595 时 GPU 帧时间不变、CPU 渲染线程从 1.13 降到 0.85 ms。

**目标**:不降帧率,把所有 3D 模型升级为圆润、精致的暖色卡通风格;角色从 4 种扩到 8 种,玩家自选形象。
做法是先降 draw call 打地基,再用省下来的余量按镜头曝光度加细节。

## 2. 范围

**做**:

- 8 种酒客(狐狸、熊、猪、猫、乌龟、羊驼、猴子、鳄鱼)与椅子
- 道具:左轮、卡牌(3D 牌体与牌面/牌背)、目标立牌架、烛台、牌桌、吊灯、枪口焰与硝烟、吧台啤酒杯
- 房间:墙地材质、梁柱与线脚、壁炉、吧台、门窗、墙饰、角落摆件、地毯、接地贴花
- 光照与材质:曝光、环境光遮蔽、金属、阴影策略、调色
- 自选形象:主菜单与等待厅界面 + 联机协议 v5
- 性能测量工具与预算测试

**不做**:2D 界面/HUD 改版、新玩法、画质档位、德州扑克、外部美术资源(.glb/图片)、描边或卡通渲染、ReflectionProbe、
牌桌上的啤酒与筹码、卡牌宫廷肖像。

## 3. 已定决策

用户决定:

1. 全部继续用代码生成;运行时用 SubViewport 绘制的贴图(做法同现有牌面)算作代码生成。
2. 目标硬件:主流机器 1080p 稳定 60 帧(M1 及以上 Mac;Windows 带 GTX 1060 级独显或 Iris Xe / 780M 级核显),不做画质档位。
3. 画风:保留暖色卡通,做精致、更圆润;不做描边/卡通渲染,不走阴暗写实。
4. 角色:保留四个现有物种的辨识(狐狸礼帽、熊圆顶礼帽、猪鸭舌帽、猫牛仔帽)与关键尺寸,体型可以重塑。
5. 新增乌龟、羊驼、猴子、鳄鱼,共 8 种。
6. 玩家自选形象,房主先到先得、同桌不重复,选择记在本机;需要协议 v5,旧版本不能同桌。
7. 路线:先打地基再加细节,按镜头曝光度排序;拆成 4 个子项目,各自出实施计划、各自发版:
   ① 地基与观感修正 → ② 角色 → ③ 道具 → ④ 场景。

设计默认(用户授权自审确认):

8. 保留 ACES 暖色调;按实测不降曝光,靠给角色底色设上限解决过曝(见第 9 节「裁定」);只有压不住时才换 AgX。
9. 月光只让窗墙投影,酒客不再有月光影子。
10. 牌桌上不摆啤酒和筹码。
11. 前墙加西部弹簧门;主菜单摆空椅子;后吧镜子用假的烟熏镜。
12. 左轮加粗 1.2–1.3 倍,重调举枪姿态。
13. 牌面做烫金边框和奶油底,牌背改 5 孔弹巢,不画宫廷肖像。
14. 测试只在原意不变时调整,每处在实施计划里单独标出。
15. 启动时间最多多 200 ms。

### 4.2 验证方法

1. **性能**:`tools/perf_probe.gd`(子项目①改造后)每个子项目发版前后各跑,取 3 次中位数,每次 300 帧,接电源:

4. **集显**:Mac 上用 `--rendering-driver vulkan`(MoltenVK)粗略模拟较高的单次 draw 开销;有 Windows 集显机时实测。

## 5. 共享技术架构(详见子项目①设计 A 节)

- **MeshKit 网格缓存**:同参数返回同一份只读网格,触发 Forward+ 自动实例化;`SHADOW_AUTO` 让节点自身尺寸 < 8 cm 的件不投影。
- **MeshForge 合批构建器**:配方 → 纯数组(可在工作线程跑)→ 主线程 commit 成共享 `ArrayMesh`。**逐顶点复刻 Godot 基础体**,
  因为 Metal 上运行时读 `PrimitiveMesh` 数组每次约 1.2 ms(GPU 回读);游戏代码禁止 `get_mesh_arrays` / `surface_get_arrays` / `get_faces`。
  顶点布局:COLOR = sRGB albedo + AO,UV2 = (roughness, metallic),CUSTOM0 = 部件局部坐标 + 种子(木纹 part space)。
- **着色器**:新增 `patron`(实例参数 `fade` 取代出局时的材质补间)、`prop`、`bottle_glass`,②再加 `patron_eye`,共 ≤ 4 个;③④不再新增。
  `wood.gdshader` 加 `use_part_space`,`flame.gdshader` 改实例参数。禁止 `duplicate()` 复制 ShaderMaterial 做变体。
- **阴影**:投影灯固定 3 盏;月光 `shadow_caster_mask` 只含窗框与窗墙(`LAYER_MOON`);地板与三面实墙的护墙板/灰泥不投影,压条照常投影。
- **合批**:按动画枢轴合并、不跨枢轴;静态物按区域合并,禁止全局合并;相同物体共享资源;大量小件用不透明 MultiMesh。
- **红线**:不改 `project.godot`(否则须重装);新静态缓存在 `main.gd:_exit_tree` 释放;工作线程只做数组运算。

### 裁定(子项目设计之间的冲突)

- **去过曝**:保持 ACES、曝光 1.32 不降(实测降到 1.0–1.1 整间屋子暗 14–16%);酒客调色板按最大通道等比压到 ≤ 0.65,眼白 0.65 档,爪子 ×0.8。
  第 3 节第 8 条据此修订;②③按 0.65 上限配色。
- **过曝口径**:脸部/爪子「发白」= Rec.709 亮度 ≥ 0.85 的像素 ≤ 5%;整帧任一通道削顶 ≤ 1%。
- **中弹后左轮落点**:落在本人面前的桌沿(①B3.6),③不改为落地。
- **每名酒客统计口径**:实例数含椅子(①为 17,②要做到 ≤ 16),材质数不含椅子(椅子木纹算场景共享材质)。

## 11. 发版

- 原定每个子项目单独发版;与德州合并后改为一起发 0.7.0,见第 13 节。发版走 `release-update` 流程(`build.json` 的 `build` 加一、改 `version`)。
- 子项目①③④是纯视觉改动(脚本、shader、新 class_name 文件都在 pck 里),可在线更新;若改了 `project.godot` 则须把 `base_build` 设为本次 `build`(须重装)。
- 子项目②改协议(v5),新旧版本不能同桌,房间列表会显示「更新后加入」。
- 推送远端与发版(推出去撤不回)须用户确认后才做。

## 12. 风险

- **几何改动破坏动画**:第 10 节的约束全部有测试兜底;合并阶段要求像素一致,把「合并」和「换造型」分开。
- **构建耗时**:高细节酒客单个约 20–40 ms,加入/复活都会重建(`table_world.gd:76, 105`);按物种缓存、启动时预建。
- **首次编译卡顿**:新 shader 启动时离屏预热。
- **集显 CPU 开销**:draw call 预算是主要保险;M3 上帧时间看不出 draw call 的差别,要看 CPU 渲染线程时间。
- **测试过于保守**:如头部合并后 `test_hand_visibility` 的 AABB 判定误报,改为三角形射线判定(原意不变),在计划中标出。
