# 骗子酒馆(Liar's Tavern)设计文档

- 日期:2026-08-14(2026-10-06 修订:牌桌改为 3D 表现,补充局域网细节)
- 状态:已确认
- 平台:桌面客户端(Windows / macOS),Godot 4.7(Forward+ 渲染),GDScript,中文 UI
- 联机:局域网 2–4 人,纯真人对战

## 1. 概述

《骗子酒馆》是一款局域网多人吹牛出牌游戏。玩家轮流盖牌打出并声称是本局目标牌,
下家可以质疑;质疑判定后输的一方对自己进行一次俄罗斯轮盘射击,最后存活者获胜。

首版范围:仅"骗子牌"模式、2–4 名真人玩家、**3D 酒馆牌桌(第三人称越肩视角)**、局域网自动发现 + 手输 IP 直连。
明确不做:AI 补位、骗子骰模式、互联网联机、断线重连(游戏中断线即淘汰)、外部美术资源(全部程序化生成)。

## 2. 游戏规则(骗子牌)

### 2.1 牌堆与发牌

- 牌堆共 20 张:Q×6、K×6、A×6、鬼牌×2(鬼牌为万能牌,视同任意目标牌)。
- 每小局开始:随机抽定目标牌型(Q / K / A 之一),每名存活玩家发 5 张手牌,余牌弃置不用。
- 首小局随机确定起始玩家;之后每小局由上一小局开枪者(若存活,否则其下家)先手。
- 行动顺序按座位顺时针轮转,跳过已淘汰玩家和本小局手牌已空的玩家。

### 2.2 回合行动

轮到某玩家时,二选一:

1. **出牌**:盖着打出 1–3 张手牌,声称"这些全部是目标牌"(允许说谎)。
2. **质疑**:翻开上家刚打出的那组牌进行验证。本小局第一个行动者只能出牌(没有可质疑对象)。

回合限时 30 秒:超时由房主端代为打出手牌中最靠前的 1 张(最少合法出牌),防止挂机卡死全场。

### 2.3 质疑判定

- 翻开的牌**全部**是目标牌或鬼牌 → 质疑失败,**质疑者**开枪。
- 只要有一张不是 → 说谎坐实,**出牌者**开枪。

### 2.4 左轮手枪(俄罗斯轮盘)

- 每名玩家一把 6 膛左轮,整局(match)开始时装 1 发子弹于随机膛位(1–6 均匀随机)。
- 每次开枪扣一次扳机;空枪后弹巢前进一格,同一玩家下次开枪命中概率递增,第 6 次必中。
- 中弹 → 立即淘汰(整局内不再参与)。
- 每次开枪(无论结果)结束当前小局:重抽目标牌、重新发牌,进入新小局。

### 2.5 手牌打空与强制验证

- 手牌打空的玩家本小局内被轮转跳过,处于安全旁观状态。
- 若场上仅剩一名存活玩家手中有牌,该玩家必须出牌,且系统自动翻牌验证(等效被强制质疑),按 2.3 判定。

### 2.6 胜负与再来一局

- 最后存活者获胜。结算画面展示胜者与各玩家存活轮数。
- 结束后所有人回到等待厅,可直接再开一局(重置左轮与牌堆)。

## 3. 总体架构

### 3.1 权威模型

- **房主权威(listen server)**:房主进程同时是服务端与玩家。全部规则逻辑(`src/core/`)只在房主端执行。
- 客户端只发送**意图**(出牌 / 质疑 / 准备),房主校验合法性后推进状态机,再向每个玩家定向下发其**可见视图**。
- 手牌、弹膛位置等秘密信息永不发送给无权查看的客户端,从协议层面杜绝作弊。

### 3.2 分层与目录结构

纯逻辑与表现分离:`core/` 与 `net/` 中的纯模型不依赖节点树,可被 GUT 直接单测;
3D 表现层(`world/`)只消费网络层下发的视图与事件,从不参与规则判定。

## 4. 网络设计

### 4.1 房间发现(双通道)

- 房主每 1 秒发送一次发现报文(JSON):房间 id(建房时随机)、房名、房主昵称、人数/上限、协议版本、实际游戏端口。
- 发送目标:`255.255.255.255`、按各网卡私网/链路本地 IPv4 推测的子网定向广播地址(拿不到掩码,按 /24、/23、/22、/21、/20、/16 及私网段自身前缀逐一推导,真实子网的广播地址必在其中)、`127.0.0.1`;
  对端口 `47800–47803` 各发一份——同机多开时每个实例绑定其中一个空闲端口,因此同机最多 4 个实例都能自动发现房间。
- 客户端主菜单绑定 `47800–47803` 中第一个空闲端口监听,按房间 id 去重(同一房间优先保留非回环 IP),3 秒未再收到即移除。
- 兜底:房间列表下方常驻"输入 IP 直连"入口,支持 `IP` 与 `IP:端口` 两种写法(中文输入法的全角冒号/句号/数字自动转换);
  等待厅向所有人显示房主的局域网地址,实体网卡排在虚拟网卡(WSL/Hyper-V/VirtualBox/VPN 等)之前,同类按 192.168 → 10 → 172.16 排序,「复制」取最可能连上的第一个。
- 房主连续 3 轮广播都没能发到任何局域网目标时(未授权本地网络、网卡异常等),等待厅显示红字提示,请其他人改用 IP 直连。
- 不可信输入一律在边界校验:发现报文的人数/上限/端口越界即丢弃,房间列表最多 64 条、每帧最多处理 64 个报文;握手昵称超长直接拒绝。
- 协议版本号不匹配的报文直接忽略;直连时版本不匹配由握手拒绝并提示升级。

### 4.2 游戏通信(ENet,默认端口 `47810`)

- 房主建房时优先绑定 `47810`,被占用则依次尝试 `47811–47819`(与发现端口段错开),实际端口写入发现报文与等待厅 IP 展示。
- 客户端发起连接后 8 秒内未完成握手即判定失败并提示。

客户端 → 房主(意图):

| 消息 | 载荷 | 说明 |
|---|---|---|
| `join_request` | 昵称、协议版本 | 连接建立后握手 |
| `intent_play` | 手牌下标数组(1–3 个) | 请求出牌 |
| `intent_challenge` | 无 | 请求质疑上家 |
| `lobby_ready` | bool | 等待厅准备/取消 |
| `look` | 视线落点(本人座位坐标系)、脖子偏移(座位坐标)、是否由玩家控制 | 不可靠有序、独立通道;约 10 次/秒,静止时 0.4 秒心跳 |

房主 → 客户端(视图与事件):

| 消息 | 范围 | 内容 |
|---|---|---|
| `join_accepted` / `join_denied` | 定向 | 握手结果(拒绝时附原因:满员/已开局/版本不符) |
| `lobby_state` | 广播 | 等待厅名单(昵称/准备/房主标记)与房间名、房主地址 |
| `kicked` | 定向 | 被房主请出,客户端随后自行断开 |
| `state_public` | 广播 | 目标牌、当前行动者、各玩家手牌张数、上家声称数量、存活状态、各玩家已扣扳机次数、小局号/阶段。每次状态变更全量推送。 |
| `state_private` | 定向 | 本人手牌 + 小局号(客户端据此等待新小局手牌到达后再播发牌动画) |
| `game_events` | 广播 | 事件数组:`played`/`turn`/`reveal`/`gunshot`/`eliminated`/`round_started`/`match_over`(翻牌时才公开那组牌;弹膛位置永不下发) |
| `intent_rejected` | 定向 | 错误码(非你回合 / 下标越界 / 张数非法等) |
| `look_relay` | 转发给其他成员 | 某位玩家的视线落点,原样转发 `look`(不回发给本人) |

- 非法意图房主直接拒绝;客户端 UI 同时做前置禁用(按钮置灰),双重防护。
- 状态量小,采用全量推送,避免增量同步的一致性问题。
- 回合计时由房主权威:交出回合的批次计时 = 30 秒 + 客户端尚未演完的演出估算(`pacing.gd`;开局另加开场运镜 `Pacing.INTRO`),
  非当前玩家断线等不换人的批次只顺延本批演出时长而不重置;剩余时间随公共状态下发(`turn_time_left`),客户端倒计时环据此显示(最多显示 30 秒),与房主同时归零。
- 不能质疑自己的出牌(断线后轮转回到出牌者本人时,房主与界面都会拒绝)。
- 视线同步(协议 v2,v3 起带脖子偏移):各玩家的角色看向自己光标所指之处,按住 WASD 移动头部、脖子自动伸缩(最远 0.85 米,
  越远越往上探;松开停在原处,按反方向收回),其他人屏幕上同步。脖子只传目标偏移,各端的弹簧自己插值。每台机器都把自己摆在前排,
  所以落点按发送者自己的座位坐标系传输,接收端换回本地座位;1.2 秒收不到即视为释放,看回桌心交还演出。
  镜头拍特写或结算时不发送、不应用,伸出的脖子全部缩回。消息名排在 `join_*` 之后,握手消息编号不变,旧版本仍能收到"版本不符"的拒绝。

### 4.3 在线更新

游戏内容(脚本、场景、资源)打成一个几百 KB 的 pck,引擎本体不变;更新只换 pck。

- **版本**:`build.json` 里的 `build` 每次发布加一;`base_build` 是这份内容能叠加到的最旧安装包——`project.godot`
  改过(新增自动加载、渲染设置等)就必须重装,发布脚本发现它变了会要求把 `base_build` 设成本次 `build`。
- **签名**:清单(build、版本、引擎、平台、pck 的 SHA-256 与大小、更新说明)用发布者的 RSA 私钥签名,私钥只在发布者电脑上
  (`~/.config/liarstavern/update_signing_key.pem`,`tools/make_update_key.gd` 生成,务必备份),公钥嵌在游戏里。
  任何来源(包括局域网里冒充的房主)都只能转发官方签过名的包;下载完再逐字节核对。
- **生效**:启动引导 `UpdateBoot`(第一个自动加载,属于安装包、永不随更新替换)在其他脚本载入前把 `user://updates/` 里的
  更新包叠加进来(`load_resource_pack` 覆盖同名文件,新增的 class_name 一并登记)。只叠加比安装包新、引擎相同、安装包
  不旧于 `base_build`、文件校验通过的包;每次启动都重新验清单签名(`current.json` 记的校验值必须与签名清单一致)。
  更新后的内容连续 2 次没能在主菜单稳定跑 2 秒就丢弃,回到安装包自带的版本;启动参数 `-- --no-update` 也会丢弃(手动退路)。
- **局域网来源**:房主开房时在游戏端口号的 TCP 上提供极简 HTTP 文件服务(只回答 `/<平台>/manifest.json`、`manifest.sig`、
  `game.pck`),内容是自己正在运行的那份签名包;发现报文带 `build`/`ver`/`update`。房间列表对比自己新的房主给出
  "更新"按钮(只对同平台,报文带 `plat`),协议不兼容的房间显示"更新后加入"或"版本不同";直连被拒"版本不匹配"时也会去问房主。
  文件服务限制总连接数、单地址连接数、请求头长度、空闲与总时长,客户端不跟随重定向。
- **互联网来源**:`BuildInfo.FEED_URL` 指向一个静态目录(布局同上,按平台分子目录),启动时静默检查一次;留空则只走局域网。
  现在是 GitHub 仓库的 `updates` 分支,经 `raw.githubusercontent.com` 读取(不跳转);`tools/publish_update.sh` 每次强推一个提交。
  pck 按 build 命名(清单 `pck_file`:`game-b<build>.pck`),CDN 缓存不会把新清单和旧 pck 配在一起;房主同时以 `game.pck` 提供给旧客户端。
- **发布**:`tools/release.sh [更新说明]` 导出两个平台的安装包、签名、把清单附进安装包(macOS 放进 `.app/Contents/Resources`
  并重新 ad-hoc 签名;Windows 的 exe 与 pck 分开放在同一文件夹),并在 `build/update/<平台>/` 备好可直接上传的更新文件。
- 跨平台不能互相更新(各平台导出的 pck 不通用);引擎升级或 `base_build` 变了只能重装完整安装包,界面会说明原因。

## 5. 界面流程与 3D 牌桌演出

```text
主菜单 ──建房──▶ 等待厅(房主) ──全员准备+开始──▶ 牌桌 ──▶ 结算 ──▶ 等待厅
   │                                              ▲
   └─选房间/输IP──▶ 等待厅(客) ────────────────────┘
```

### 5.1 常驻 3D 酒馆

- 整个游戏只有一个常驻 3D 场景,2D 界面叠加其上:
  - 主菜单:相机缓慢环绕昏暗的酒馆,桌上烛火摇曳;
  - 等待厅:已加入的玩家以酒客形象依次落座,离开则起身消失;
  - 开局:相机移到自己角色的右肩后上方,切换为第三人称越肩视角(自己的角色、整张牌桌与所有对手同时在画面中)。
- 场景构成:木质酒馆房间、圆桌与桌布、吊灯(体积光束)、烛台闪烁、壁炉火光、吧台酒瓶与木桶。
- 画面:ACES 色调映射、辉光、SSAO、体积雾与浮尘粒子;全部材质由着色器程序化生成。

### 5.2 角色与桌面

- 酒客:程序化卡通角色(每个座位不同帽子与配色、大眼睛),呼吸待机,眼睛看向当前行动者,轮到时前倾;
  头顶铭牌显示昵称、手牌数、6 格弹巢图标(已扣扳机次数),出局后变灰倒伏。
- 每人面前一把左轮;桌中央为目标牌立牌与出牌区。
- 自己的角色把手牌扇形举在右胸前、牌面朝向越肩镜头(略放大保证可读;他人客户端看到的是牌背):鼠标悬停抬起、点击选中(或数字键 1–5),
  `Enter` 出牌、`空格`/`C` 质疑;HUD 按钮同步可用。

### 5.3 演出序列(事件驱动,期间锁输入)

- `round_started`:收走旧牌 → 中央目标牌立牌翻转揭示 → 牌从中央弧线飞向各座位(自己的牌落入手中翻面)。
- `played`:出牌者伸手,牌以弧线飞到桌中央盖放,对话气泡显示声称("2 张 Q")。
- `reveal`:质疑者拍桌 + "骗子!"气泡(系统强制验证则响铃提示);相机俯视出牌区,牌逐张翻开(真牌绿光、假牌红光)→ 大字判定。
- `gunshot`:相机聚焦开枪者,左轮举至太阳穴,转轮旋转 + 心跳 + 暗角收紧;
  空枪"咔哒"(角色松一口气)或中弹(枪口焰、硝烟、闪光、震屏、角色倒下变灰)。
  自己开枪时与他人同一套演出(镜头转到自己角色正面特写),中弹后画面短暂染红并转为俯视观战视角。
- `match_over`:相机环绕胜者,结算面板展示胜者;房主可带全员回等待厅。

### 5.4 HUD

左上目标牌与小局号;顶部回合横幅与环形倒计时;底部出牌/质疑按钮;右侧事件滚动日志;左下自己的弹巢图标。

## 6. 容错与错误处理

- 游戏中玩家断线 → 立即淘汰并广播提示,游戏继续;若仅剩 1 名存活者则其直接获胜。
- 房主断线 → 房间解散,所有客户端弹窗提示并返回主菜单(listen-server 固有限制,首版接受)。
- 等待厅断线 → 移出玩家列表并广播更新;被踢出的玩家收到明确提示而非"房间解散"。
- 加入超时(8 秒)、端口被占用(自动换端口,全部失败才报错)、房间已满 / 游戏已开始 / 版本不匹配,均在客户端给出明确提示。
- 所有网络回调经统一错误出口处理,UI 始终给出明确提示,不静默失败。
- 牌面离屏纹理在无渲染环境(headless)下退化为纯色纹理,保证无头联机冒烟可运行。
