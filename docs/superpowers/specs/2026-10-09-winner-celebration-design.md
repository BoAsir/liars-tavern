# 结算庆祝:胜者舞蹈与礼炮设计(2026-10-09 用户追加)

> 用户原话:「再加个胜者的结算动作或舞蹈 还有礼炮效果」。
> 三种玩法(骗子酒馆、德州、炸弹猫)的结算都加:胜者跳舞、其他人鼓掌、桌边礼炮喷彩纸。决定由协调方给出,本文记录决定与实现。

## 1. 决定

### 1.1 胜者跳舞
- 新文件 `src/world/patron_dance.gd`(`PatronDance`):挂在酒客下的逐帧驱动,在 Patron 的待机之后同一帧覆盖身体、头、手臂、帽子、腿、耳朵、尾巴。
- 5 支舞,按物种 + 种子挑一支(`PatronDance.pick`,确定性),一直循环到收起:
  - **扭腰挥手**:屁股左右扭(两拍一来回),双手举成 V 字跟着腰左右挥,头往反方向歪;
  - **迪斯科**:一只手每拍在「指向右上」与「甩到身侧下方」之间换(快到位、停住),另一只手叉在身侧,每 8 拍换手;头每拍点一下;
  - **转圈**:8 拍一轮——前 4 拍原地蹦、左右轮流挥拳,第 4 拍蹲一下,蹦起来原地转一整圈(双手平举),落地「锵锵」举 V;每轮换方向;
  - **小鸡舞**:16 拍一轮——鸡嘴(手在脸前开合、头往前啄)、扇翅膀、扭屁股、拍手各 4 拍;
  - **抛帽接帽**:帽子飞起来转两圈翻一个跟头、落回头上压扁一下,接着压帽檐致意,再扭腰挥手。
- **坐着跳**:腿是一整块坐姿网格,站起来会露出弯着的腿悬在半空,所以做上半身的大动作 + 屁股离座的小蹦(腿跟着抬起),
  转圈时腿绕髋部的竖直轴跟着身体转(转得快,膝盖扫过椅背只有一瞬)。
- 节拍 124 BPM;开头 0.4 秒从当时的姿势平滑混入。
- 表情:眯眼笑(^ ^)、开心的眉毛、耳朵随拍扇、尾巴摇得飞快(着色器尾巴相位每帧往前推);头边轮流冒 3 个音符 ♪
  (一个 MultiMesh,不打光的纯色,不投影,只在跳舞时存在)。
- 跳舞、鼓掌时牌扇收起(手会穿过胸前的牌),收起舞步时放回。
- 跟随 `Engine.time_scale`,场景树暂停时停住(走 `_process` 的 delta)。
- `Patron.reset_pose` / `die` 先 `stop_dance`:帽子、腿、身体扭转与位移、耳朵、尾巴、牌扇、脖子、表情偏移复原,活着的人双手搭回桌上。
- 第一人称:结算时镜头离座环绕,`SeatCamera` 每帧判断后把自己的头露出来,看得到自己跳舞 / 鼓掌。

### 1.2 其他人
- 活着的没赢的人(包括本机自己)坐直了鼓掌、看向胜者:两只爪子停在以肩为心、一臂长的球面上,真的拍到一起;
  一阵拍 6–11 下、歇 1.2–2.6 秒,歇的时候有时举拳欢呼一下;每人节奏、相位不同。
- 出局 / 炸飞的人保持倒下、褪色、头顶转星星,只隔 1.6–3.8 秒抽一下手。
- 鼓掌气泡没有做(可选项,省掉)。

### 1.3 礼炮(礼炮 = 玩具小炮)
- 摆在**胜者面前的桌沿两侧**(沿桌沿切向各偏 0.5 m,离桌沿往里 0.13 m),炮口仰 72°、往胜者那边偏 78°:
  两股彩纸在胜者头顶交叉,落在胜者身上、面前的桌沿和地上。从胜者特写环绕(骗子酒馆、炸弹猫)与整桌环绕(德州)都在画面里。
  没有胜者酒客时(胜者已离开)摆在本机座位对面的两侧。
- 外观:木头炮架、两只红轮子 + 金轮毂、粉 / 奶白 / 薄荷 / 奶黄条纹的胖炮管、金色翻边炮口、炮尾一根亮着火星的引信;
  一份合并网格(prop 材质),不投影;开演时「啵」地弹出来冒一小团烟。
- 开炮:整门炮往后一坐、压扁再弹回,炮口一缕烟、一小撮金色火星(`Fx.sparkles`),「砰!」(cannon_pop)。
- 节奏:开演 0.55 秒后第一炮两门齐发(最大:每门 150 片彩纸 + 10 条彩带),之后每 3.4 秒左右轮流一门(100 + 7)。
- 彩纸(`ConfettiFx`):GPUParticles3D 一次性喷发,运动写在 `confetti_motion.gdshader`(粒子着色器):
  上冲阻力小(1.6/秒)、往下飘阻力大(4.0/秒,终端速度约 0.65 m/s)、左右飘、绕随机轴翻滚;
  落到桌面(桌心与半径按当前牌桌)或地板就平躺不动,生命最后一段缩没(不透明,不用排序)。
  方片与长纸条两种,粉彩但够艳的 8 色(太淡会被夜里的暖光与色调映射冲成白)。卷曲彩带是绕成弹簧的窄纸带网格,翻得慢。
  画法 `confetti.gdshader`:不打光,按纸面朝向镜头的程度明暗,翻滚时一闪一闪;不投影。
- 上限:场上彩纸 + 彩带按每股的数量与寿命记账,任何时刻不超过 **400**,超了这一炮少喷一点。
- 网格与材质按参数缓存(`MeshForge.cached` + `ConfettiFx` / `PatronDance` 的静态缓存,main 退出时释放);不 duplicate 材质。

### 1.4 音效(`Sfx`,程序化)
- `cannon_pop`:往下滑的闷「砰」+ 短爆裂噪声 + 越来越稀的纸屑沙沙声;
- `fanfare`:卡通小号「哒哒哒—哒!」(三个短 G4 接长 C5 大三和弦 + 一声小钟),开演时放,代替结算原来的 `win` 铃声;
- `applause`:起头密、慢慢稀下来的一阵掌声,垫在小号底下。
- 世界层不直接碰 autoload:`Celebration.sfx` → `TableWorld.sfx` → main 接到 `Sfx.play`;静音时 `Sfx` 自己不出声。

### 1.5 接入三种玩法
- `TableWorld.celebrate(winners, seed)` 开演、`stop_celebration()` 收起;`revive_all`(回等待厅、新一局)、`clear`(离开)、
  三种牌桌屏幕的 `_exit_tree` 都会收起。纯本地表现,不发网络消息;各端从自己收到的事件开演。
- 骗子酒馆 `match_over`、炸弹猫 `match_over`:胜者跳舞(代替原来的举手蹦三下),特写环绕机位不变(抽成 `TableWorld.winner_orbit`)。
- 德州 `session_over`:盈亏第一的人跳舞,**并列第一的都跳**(`PokerDirector.top_ranked`),整桌环绕机位不变;礼炮摆在第一个胜者面前。
- 舞步种子由各端都收到的对局信息算(骗子酒馆:胜者 + 局号;炸弹猫:胜者 + 名次;德州:胜者 + 结算行数),同一个胜者各端跳同一支舞。
- 节奏、计时、结算面板、自动返回都不变(导演里等待的时长没动)。

## 2. 约束核对
- 不改 project.godot、不改协议;`src/**` 没有运行时读网格数组;不 duplicate ShaderMaterial;特效一律不投影。
- `test_scene_budget` 的静止酒客网格数不变:音符、礼炮、彩纸只在庆祝期间存在。
- 新静态缓存(`PatronDance._cache`、`ConfettiFx._cache`)在 main `_exit_tree` 清掉。

## 3. 实施记录

### 3.1 文件
- `src/world/patron_dance.gd`:舞步、鼓掌、抽手、音符;`src/world/patron_3d.gd`:`dance / clap / twitch / stop_dance / is_dancing / dance_routine`。
- `src/world/celebration.gd`:开演、礼炮摆放与开炮节奏、彩纸记账、收起。
- `src/world/confetti_fx.gd`、`src/world/shaders/confetti_motion.gdshader`、`src/world/shaders/confetti.gdshader`:彩纸与彩带。
- `src/world/props/party_cannon.gd`:玩具礼炮。`src/world/fx.gd`:`sparkles`。
- `src/world/table_world.gd`:`celebrate / stop_celebration / is_celebrating / winner_orbit / orbit_start`、`sfx` 信号。
- `src/ui/sfx.gd`:三个音效。三个导演、三个牌桌屏幕、`main.gd` 的接入。
- 工具:`tools/celebrate_stage.gd`(三种展台上摆一场庆祝)、`shot.gd --celebrate[=秒] [--celebrate-hud]`、
  `perf_probe.gd --celebrate`(机位 `celebrate` / `celebrate_table`,预算同其余机位 ≤ 900 draw call)。

### 3.2 调参过程
- 第一版彩纸太淡(粉彩 × 色调映射几乎全白)、太小、往胜者背后飞(炮口朝外),桌上几乎落不到:
  颜色加艳、片加大到 3.4–5.2 cm、上冲 / 下飘分开两种阻力、炮口仰角 52° → 72°、往胜者那边偏 26° → 78°。
- 鼓掌第一版只给手臂方向,手停在臂长末端、两爪永远差 30 cm:改成按「手在肩球面上的位置」反求方向(`PatronDance.palm`)。
- 举 V 字的手藏在大头后面:V 张开(手的横向分量 0.45 → 0.62–0.7)。
- 炮口的烟太白太大像棉花球:烟量减半、颜色压灰。

### 3.3 测试
- `tests/test_celebration.gd`(20 个):舞步起停与 reset_pose 复原(帽子、腿、身体、牌扇、手臂)、转圈中途停下复原、
  挑舞确定性且 5 支都挑得到、每支舞在 8 个物种上跑满一轮不出错、音符只在跳舞时存在、死人不跳不拍、
  旁人鼓掌 / 死人抽手且仍倒着、两爪真的拍到一起、礼炮与彩纸的创建和收起释放、第一炮最大且之后轮流、
  记账上限与真实帧下的粒子节点上限、revive_all / clear 收起、再开演顶掉上一场、没有胜者酒客时照样开炮、
  音效走世界信号且都有音量表项、德州并列第一与全员平局、骗子酒馆导演 match_over 开演且结算面板照常弹出。
- `tests/test_sfx_celebration.gd`:三个音效的时长、非静音、几乎不削波、结尾收干净。
- 整局流程测试补断言:德州第一名跳舞、自己与迟到者鼓掌、退场收起;炸弹猫胜者跳舞、炸飞的不鼓掌、退场收起。
- `tests/test_perf_budget.gd`:两个庆祝机位有预算。

### 3.4 性能(M3,游戏渲染配置 budget 组;机器发热,同一轮里不开庆祝的 overhead 也是 12.1 ms)

| 骗子酒馆 celebrate | 278 | 12.3 ms |
| 骗子酒馆 celebrate_table | 341 | 12.1 ms |

draw call 都远低于 900;帧时间与同一轮不开庆祝的机位差在 0.3 ms 的噪声里。

### 3.5 已知问题
- 结算面板(居中、480–560 px 宽)弹出后会挡住画面中央的胜者:特写环绕一直把胜者放在画面中心。
  面板弹出前的 2.2–2.4 秒(开炮、第一股彩纸、舞步开头)完全看得到,之后彩纸、礼炮、旁人鼓掌在面板四周照样看得到,舞步大部分被挡。
  按决定没有改结算面板与机位;以后可以考虑让面板偏到一侧,或给环绕加个横向取景偏移。
- 转圈时膝盖会在一瞬间扫过椅背(腿是整块坐姿网格)。
- 德州并列第一时礼炮只摆在第一个胜者面前,其余并列者只跳舞。
